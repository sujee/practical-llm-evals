Full testing methodology
  • TTFT runs from request dispatch to the first non-empty content or reasoning delta.
  • Tokens/sec divides completion tokens by elapsed streaming time after that first delta.
  • End-to-end latency runs from request dispatch until the response stream closes.
  • One warm-up request runs per model. It is excluded from latency summaries but included in test time, token usage, and cost.
  • Total run time is wall-clock time; parallel model times are not summed.
  • Cost uses each model's displayed input and output price per million tokens; models without pricing remain unpriced.
  • Output health is diagnostic only. Missing final content and unusually short output produce warnings without invalidating runs; reaching the configured token ceiling is expected.
  • The quick preset uses a short, unpadded prompt and targets exactly 1,024 output tokens at concurrency 3. Actual token counts come from server usage.
  • TTFT therefore represents short-prompt latency. Long-context prefill performance should be measured separately with controlled input sizes.
  • Models run in parallel; measured runs for a given model remain serial. Use concurrency 1 for an isolated latency baseline.
  • Model scheduling order is randomized and recorded in the raw export to reduce time-of-run bias.
